# Compatibility and acceptance status

## Delivery boundary

This project is a browser reimplementation of the Windows Me desktop with working JavaScript applications and a persistent virtual drive. It is **not a complete Windows Me clone at the binary, kernel, hardware, feature or verified pixel level**. A full original-software environment would require a separate machine emulator and a licensed Windows installation with its system binaries.

“Implemented” below means there is application logic for that workflow. It does not imply that every historical option, file format or UI pixel is reproduced.

## Automated verification

Run `npm test` and `npm run check`. Tests cover the application models and key integration paths using simulated browser APIs. Tests intentionally inject a failed IndexedDB transaction, concurrent drive writes, invalid backup entries, failed graphics draws, illegal game moves and malformed page-tool inputs.

The DOM smoke test creates and disposes every one of the 60 registered applications. Separate assertions save a Unicode note through the actual shared Save dialog, reopen it, reject an unsaved close, exercise window state transitions, execute terminal file operations and BAT control flow, and verify that page tools read/write the same virtual drive.

The fake graphics/media layer does not certify real rendering or device behavior. The page-tool registry in that test is a mock; a supported browser WebMCP context was unavailable.

## Browser acceptance checks still required

The session's preview server was running, but the provided browser refused the preview address. Therefore these checks were **not completed**:

1. Screenshot comparison at 800×600 and 1024×768 at 100% scale, including menus, font baselines, icons, inactive windows and app layouts.
2. Real WebGPU shader compilation and device-loss recovery, real WebGL fallback, and visual comparison of the CPU fallback.
3. Host-file import/export, native printing, full-screen behavior, clipboard permissions and browser-reserved keyboard combinations.
4. Microphone recording and playback, mute/volume behavior and every target browser codec.
5. Two consecutive Movie Maker exports containing image, title and trimmed video clips; output duration and audio-track inspection; preview playback after export; cancellation during a slow/invalid clip load.
6. Actual service-worker install, offline reload and update activation.
7. Supported-browser WebMCP registration and successful/invalid calls.

These are explicit confidence limits. The project should not be described as a fully compatible, pixel-perfect replacement for Windows Me without substantial additional implementation and reference testing.
